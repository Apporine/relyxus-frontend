# Frontend open questions and specification conflicts

The engineering contract forbids silently resolving conflicts or inventing behaviour. Each
item below states the conflict, the authority that applies, what the frontend does in the
meantime and who needs to answer.

| ID  | Topic                             | Conflict or gap                                                                                                                                                                                                                                                                                                                                                                  | Interim frontend behaviour                                                                                                                                                                                                                        | Needs answer from                            |
| --- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| Q1  | Light theme                       | UI/UX s. 6 requires System, Light and Dark themes and light-theme printing. The Obsidian package (level 4, overrides visual styling) defines dark tokens only; the UI/UX light tokens use the prohibited blue and violet.                                                                                                                                                        | Theme infrastructure supports multiple themes through `data-theme`; only Obsidian dark ships. No theme switcher is shown until light tokens are approved. Print styles are not finalised.                                                         | Design                                       |
| Q2  | Type scale and line heights       | UI/UX s. 5 scale (22/18/15/14/12.5/13) differs from Obsidian tokens (24/20/16/15/14/13.5). Obsidian gives no line heights.                                                                                                                                                                                                                                                       | Obsidian sizes are used (level 4 overrides visual styling). Line heights are set at roughly 1.33 to 1.5 and listed in the token file for design sign-off.                                                                                         | Design                                       |
| Q3  | Typeface                          | UI/UX s. 1 and 5 specify Inter; Obsidian package and engineering contract s. 22 specify IBM Plex Sans Variable.                                                                                                                                                                                                                                                                  | IBM Plex Sans Variable (higher authority for visual styling). Recorded so the UI/UX document can be updated.                                                                                                                                      | Design (document update only)                |
| Q4  | API contract                      | No OpenAPI file exists yet. UI/UX s. 19 expects generated clients; the contract forbids fabricating integration APIs.                                                                                                                                                                                                                                                            | Response shapes are defined as Zod schemas derived from Product s. 20 entities, kept in `apps/web/src/features/*/model`, used with MSW fixtures, and marked provisional. They are replaced by generated types when the OpenAPI file is published. | Backend / API owners                         |
| Q5  | Identity and session              | Keycloak realm, client type (confidential BFF or public PKCE), session lifetime, step-up MFA mechanism and SCIM-driven sign-out behaviour are not specified for the console.                                                                                                                                                                                                     | Identity and Session capability is not started; screens render against MSW session fixtures in development only.                                                                                                                                  | Security architecture                        |
| Q6  | Repository topology               | The Technology Stack Decision describes one private monorepo containing frontend, services, policy and infrastructure. This repository is frontend only.                                                                                                                                                                                                                         | `apps/` and `packages/` mirror the monorepo layout so the move is mechanical (ADR 0001).                                                                                                                                                          | Engineering leadership                       |
| Q7  | CODEOWNERS and branch protection  | Required reviewers for security, policy, workflow and evidence code need real GitHub teams.                                                                                                                                                                                                                                                                                      | No CODEOWNERS file is committed until team handles are provided.                                                                                                                                                                                  | Repository administrators                    |
| Q8  | Integration branch                | The repository has `master` (default) and `dev`. The contract says every change reaches main through a pull request but does not say whether `dev` is an integration branch.                                                                                                                                                                                                     | Feature branches are stacked from `dev`; each pull request targets the branch below it.                                                                                                                                                           | Engineering leadership                       |
| Q9  | Chart categorical palette         | UI/UX s. 17 refers to "eight categorical tokens"; Obsidian defines none.                                                                                                                                                                                                                                                                                                         | Charts use neutral greys plus semantic colours only where they carry status meaning until a palette is approved.                                                                                                                                  | Design                                       |

Shape icons (octagon, triangle, circle, info) and words always accompany colour.                                                                                                        | Design                                       |
| Q11 | Help entry point                  | UI/UX s. 6 requires help in the same place in the top bar; Figma frame 02 shows no help control.                                                                                                                                                                                                                                                                                 | The top bar includes a help control (UI/UX is authoritative for layout and interaction).                                                                                                                                                          | Design                                       |
